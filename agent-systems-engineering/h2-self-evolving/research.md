# H2 — Self-Evolving Harness — Living Research State

_Last reviewed: 2026-11-10 — integrated living synthesis (new primary evidence, matched budgets, retention, transfer and safety)_

**Category:** a system iteratively rewrites externally stored harness artifacts based on execution feedback while **executor and optimizer/evolver neural weights remain fixed**. A meta-evolver that modifies the *evolver's source code* but does not train its weights remains H2. Exclude evolver-weight learning ([H3](../h3-weight-harness/research.md)) and executor-weight co-adaptation ([H4](../h4-co-adaptation/research.md)). See [taxonomy](../taxonomy.md). This is the scheduler's **only** writable research file; [parent research.md](../research.md) is human-owned/read-only.

## Current synthesis and evidence status (2026-11-10)

**Bottom line — strengthened but qualified:** fixed-weight, repeated search over **actual executable harnesses** is feasible and can improve task scores. It does **not** establish indefinite, monotonic, transferable or cost-effective self-improvement. The strongest November contribution is not a new record score: it is experimental evidence that average gains can hide lost capabilities, cross-domain interference and higher deployment cost. This **weakens** any reading of earlier H2 results as automatically accumulating competence.

1. **What qualifies:** H2 entails an automated recurrent **propose → execute fixed-weight agent → evaluate → accept/reject/branch → reuse or revise executable harness artifact** loop. It can edit executable source, tool definitions, orchestration, skills, instructions or persistent procedural state. A one-off externally optimized harness is H1/H2-boundary evidence, **not** by itself a sustained evolving loop. A trained *neural evolver* is H3; a trained *task executor* coupled to harness changes is H4. Fitting a non-neural bandit, storing textual search guidance, or rewriting evolver **source code** with neural weights fixed remains H2.
2. **Positive results are real but conditional:** the DGM archive, AHE, Meta-Harness, SSR and MESH demonstrate alternative search operators; November's Meta² supports **task-local live edits guided by reusable textual knowledge**, and EvoGroup extends multi-component edits to shared-context retrieval. Their benchmark gains concern different editable surfaces, oracles, test protocols and compute budgets; headline percentages are not directly comparable.
3. **Search operator choice is an independent optimization problem:** DGM branches an archive, SSR races **alternative evidence-conditioned candidates**, MESH combines mutable module pools using LinUCB and code edits, Harmony retains Pareto candidates, and EvoAudit/AGE tests regression-aware parent/child decisions. These are distinct mechanisms; **more candidates, stricter gates, more traces or the best current parent are not guaranteed better**. SSR's 60% saving is on validation **executions**, not overall evolution cost; MESH matches **40 complete candidate evaluations**, not every compute component.
4. **Reliability, coverage and retention must be separated (stronger negative evidence):** *Beneath the Surface* finds simultaneous gain and loss of covered tasks in **all 16** Seed→Champion configurations; **8/11** reliability-improving champions cost more per trial. *Can Coding Agents Sustain Continual Evolution?* reports **94% → 32%** on earlier SWE tasks after later FeatureBench adaptation in one sampled stream. October's EvoHarnessBench and continual-learning studies already signaled harness-induced forgetting. Successful validation admission does not certify future retention.
5. **Task-locality may beat globally persisting edits:** Meta²'s persistent-cross-task edit ablation underperforms resetting execution-time edits; reusable *meta-skill* ≠ portable patched code. Domain-specific harness artifacts, versioned fallbacks and scoped changes should be compared against a single global mutable harness, not assumed inferior.
6. **Transfer is object- and distribution-specific:** distinguish frozen **harness code transfer** (MESH, AHE, HERA), **textual optimization guidance transfer** (Meta²), **related benchmark transfer** (EvoGroup and Harmony), and **continual performance on old tasks** (Zhao et al.). EvoGroup's GroupMemBench transfer is positive on GPT-5.5 but negative vs seed on DeepSeek. Cross-model performance with per-model retrained meta-skills is **not** zero-shot transfer of one artifact.
7. **Matched budget and independent holdout are mandatory:** *Rethinking Evaluation* finds **63.2% vs 63.2%** mean success on disjoint held-out Terminal-Bench tasks for evolved vs static harnesses; at comparable feedback budgets, direct task-solution sampling can be better. Cost must count **proposer/reflector, executions, judges, selection, invalid variants, test-time attempts, wall-clock and dollars**. Same-batch label-free adaptation (TTHE) is **transductive**, not proof of next-batch performance.
8. **Security is not implied by task performance:** executable mutation can alter permissions, egress, validator code and side-effect behavior. Harmony documents grader exploitation under a different selection gate. Reproducible candidate promotion requires a write-set allowlist, isolated execution, deterministic permission enforcement, immutable external judges/held-outs, provenance and rollback. There is **no general independent safety certification** from these benchmark papers.

**Evidence strengths:** repeated held-out evaluations, explicit candidate-evaluation caps and within-paper ablations (MESH, SSR, Meta², EvoAudit) are more informative than unbudgeted best-champion examples. **Evidence gaps:** multi-seed search uncertainty; end-to-end matched spend, especially across model providers; prospective multi-domain retention; independent exploit tests; reproductions outside author-designed simulators. All new November empirical papers should be treated as **preprints**, not established production results.

## Search-mechanism map: what actually changes and how the branch is chosen

| Method | Candidate proposal / executable mutation | Evaluation and selection / branching | Main confound or failure |
| --- | --- | --- | --- |
| **DGM** (2025) | Mutate coding-agent implementation; archive code variants | Run task suites; retain multiple lineage branches; sample archive for future children | Best-of-search and budget; archive diversity may not transfer or persist |
| **AHE / Meta-Harness** (2026) | Propose file-based tool/middleware/memory/context-code edits from traces | Evaluate changed candidate; keep/revert; search sequentially | Search cost, reused task feedback and benchmark-specific tuning |
| **SSR** (Oct) | Different **nested evidence subsets** yield separate code/control candidates | Race on shared increasingly large candidate-validation batches; promote incumbent replacement | Validation execution saving is not total-cost saving; mixed old/training/selection sets |
| **MESH-Harness** (Oct; recovered Nov) | Edit **interchangeable executable modules** from traces; recombine module pools | Full-covariance **LinUCB** predicts and explores compositions; execute 40 complete candidates | Surrogate misspecification; module interface limitation; unmatched generation cost |
| **Meta²** (Nov) | Offline refine **textual Meta-Skill**; online KEEP/EVOLVE chooses task-local executable edits | Evaluate contrastive training trajectories; hold meta-skill fixed, edit live run without resetting | Unobserved true reward at online time; overhead and safety of mid-run mutation |
| **EvoGroup** (Nov) | Confidence/outcome-based trace diagnosis updates tools, middleware, prompts, memory and skills | Iterative supervised task-feedback loop with bucketed analysis | Depends on label/oracle; cross-model/cross-benchmark gains vary; no strong universal retention claim |
| **Harmony** (Oct) | Evolve portable/context-specific tools and security controls | Pareto functional-plus-security candidates; composer chooses components | Grader hacking and incomplete independence of vulnerability tests |
| **EvoAudit / AGE** (Nov) | Diagnose trace failures; propose dependency-closed bounded changes | Regression-aware parent tie-break, comparable cost-aware gate on score ties | One search lineage per comparison; better gate is still exposed to adaptive overfitting |
| **TTHE** (July; v3 Nov) | Proposers edit executable programs from unlabeled batch traces | Judge selects on proxy execution signals within same test batch; carry chosen code forward | **Transductive** same-batch evaluation; uncertain independent future-batch transfer |

*This map describes search topology, not comparative winner rankings. In H2 no neural weights change inside the reported optimization loop, even if an algorithm stores auxiliary fitted non-neural statistics.*

## Latest primary evidence (November 2026; plus an omitted October mechanism)

### Meta² — Precomputing Reusable Knowledge for Online Harness Evolution in Long-Horizon Agents
**Source:** https://arxiv.org/abs/2611.05139 — Lingzhi Yuan et al.; **2026-11-03, arXiv preprint**. **Status:** promising controlled H2; online task-locality and meta-guidance ablations.

- **Mechanism:** offline A/B/C trajectories contrast (A) frozen task agent, (B) frozen evolver guided by current textual Meta-Skill and (C) verifier-assisted evolution on **training** tasks. Contrastive synthesis improves textual **M**, not model weights. Online a frozen-weight evolver consults M and live traces to decide KEEP or EVOLVE, modifying executable harness pieces within a task without restarting the environment; it **resets the harness between tasks**. Held-out verifier labels are not available to the deployed evolver.
- **Held-out protocol and effects:** GPT-5.6-Terra achieves **81.00% Terminal-Bench 2.1 (mean@5)** and **44.44% DeepSWE 1.1 (mean@3)**, versus shared NexAU seed **66.33/34.67** (+**14.67/+9.77 pp**). Meta-Harness in the same table reports **73.33/37.33**. A separately constructed Meta-Skill on DeepSeek-V4-Flash-0731 yields **77.67% Terminal (mean@5)**; this is a **backbone robustness test**, not transfer of the unchanged Meta-Skill between backbones.
- **Causal ablations:** online evolver with no Meta-Skill **74.67/36.44**; self-distilled M **77.00/35.56**; contrastive M **81.00/44.44**. Retaining online edits *across* tasks rather than resetting lowers to **78.33/39.11**. This supports the **separation of transferable strategy and task-specific patches**, not a claim that any global persistence must fail.
- **Cost:** aggregate offline+online **$174.91/$367.86** vs Meta-Harness **$198.85/$870.75** for the two benchmark settings; compare the same setup and distinguish **amortized offline construction** from repeated deployments. Checkpoint frequency also trades cost and responsiveness; do not present 81% as cost-free improvement.
- **Caveats:** finite benchmarks, incomplete independent replications, task-edits inherit live execution privileges, test-split contamination must be checked for verifier-assisted training. The best result is per-task adaptation, not demonstrated long-term training-free general intelligence.

### Beneath the Surface: What We Overlook When We Talk About Agent Evolution — EvoAudit / AGE
**Source:** https://arxiv.org/abs/2611.07624 — Xiaobo Wang et al.; **2026-11-05, arXiv preprint**. **Status:** particularly important **counterevidence** and operator-level diagnostic study.

- **Design:** four H2 methods (**AHE, HyperAgents, A-Evolve, GEPA**) × two harness substrates (**MiniSWE 2.4.5**, source editable; **Codex 0.143.0**, outer-layer edit only) × two task domains (**97 tau³-Banking**, **89 Terminal-Bench 2**) = **16** conditions; GPT-5.4 held fixed. Uses **eight independent task passes** for matched Seed/Champion reports. Distinguish average repeated reliability (**Avg@8**) from unique task coverage in eight attempts (**Pass@8**).
- **Non-monotonicity:** **11/16** Champions improve Avg@8; **10/16** improve Pass@8; **16/16** gain *and* lose individual covered tasks (losses 2–10 and gains 1–15 tasks in the studied conditions). One agent improves mean reliability **+5.2 points yet loses 10 formerly covered tasks**. **8 of 11** reliability-improving agents increase average deployment cost per trial; some still reduce cost-to-reach fixed coverage with fewer repeats.
- **Search mechanisms:** highest current-scoring parent is **not** highest mean future-improvement parent in any of four controlled expansion pools. Combining independently beneficial component modifications can interfere; a stricter gate can reject useful candidates. These are failure modes of **select, analyze, mutate, gate**, not evidence of model-weight forgetting.
- **Corrective method:** AGE keeps score primary but uses regression-aware **parent tie-breaking**, evidence-grounded diagnosis, dependency-closed mutation and cost comparisons for score-tied admission. Under matched **20 generations × one candidate** and a **single search seed**, AGE raises Avg@8 over reference A-Evolve: Banking MiniSWE **26.3→34.0**, Banking Codex **28.1→38.1**, Terminal MiniSWE **68.0→71.8**, Terminal Codex **68.0→73.5**. Evolution budgets remain substantial (AGE approximately **$983–$1,481** across settings); not a broad robust statistical rank of optimizers.
- **Interpretation:** retain **per-task pass→fail/gain→loss**, repeated reliability, search lineage, transfer and a cost-to-coverage curve. Improvements from AGE are promising **in-study**, not proof that a fixed gate can guarantee preservation.

### Can Coding Agents Sustain Continual Evolution without Forgetting?
**Source:** https://arxiv.org/abs/2611.03219 — Shangziqi Zhao, Yitong Zhang, Jia Li; **2026-11-02, arXiv preprint**; code https://github.com/THU-Agent/continual-harness-evolution . **Status:** strong illustrative cross-task regression, limited deployment generality.

- **Loop:** fixed DeepSeek-V4-Flash-0731 executor/evolver with AHE and Meta-Harness harness evolution across **SWE-Bench repair, SWT-Bench test creation and FeatureBench feature implementation**, in **six directed family sequences**. Previously optimized harness code/configuration is modified again as the target task family changes.
- **Contrary result:** on the paper's **sampled** SWE-Bench evaluation Meta-Harness reaches **94.0%**, then after FeatureBench evolution falls to **32.0%** on prior SWE tasks (**−62 percentage points**, approximately **66% relative** loss). This is harness-policy interference with frozen weights, **not neural catastrophic forgetting**. The paper identifies conflicts in verification rules, workflow order and time/resource allocation as explanations from execution traces.
- **Limits:** small task-family subsets and method reimplementations, sequence dependence and limited multi-seed uncertainty. The 94% is **not** an official full SWE-bench result; no proven general anti-forgetting algorithm. Evaluate all family-order checkpoints with old/new held-outs before calling evolution cumulative.

### EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts
**Source:** https://arxiv.org/abs/2611.03868 — Xinyi Xu et al.; **2026-11-02, arXiv preprint**. **Status:** new H2 application with genuine *tool/middleware* edits, but uneven external transfer.

- **Loop:** six-tool initial executable harness; group-memory interaction → reported confidence / **official correctness signal** → selected trajectories → adaptive progressive disclosure (APD), bucketed failure analysis → evolved **prompt, tools, middleware, memory and skills**. No neural evolver/executor update reported. Distinguish agent/tool redesign from mere storage of conversational records.
- **Results:** held-out **EverMemBench** with DeepSeek-V4-Flash pass@1 **71.07→89.58%** (+**18.51 pp**); other backbones also improve. This is within a related multi-party memory benchmark distribution, with supervised feedback available on the evolution split; it is not unsupervised longitudinal deployment.
- **Ablations:** component-only tool replacement **+10.90 pp**, prompt **+7.41 pp**; other modules smaller. On its **held-in process** experiment, dropping trajectory filtering improves **73.33→74.86%** under equal token allowance, i.e. filtration does **not** always help; removing APD yields **69.44%** and bucketed aggregation **67.08%**.
- **Transfer counterevidence:** evolved harness on separately unseen **GroupMemBench** scores **63.89 vs seed 61.88** (GPT-5.5) but **71.14 vs seed 74.09** (DeepSeek-V4-Flash), behind human-designed Codex **76.51** in that second setup. Do **not** generalize the positive GPT-5.5 transfer to all models. External human-harness comparison tables partly include **count-aligned projections**, not reruns on identical held-out questions. Group privacy/permissions, judge calibration, rotation of holdouts and search costs are insufficiently tested.

### MESH-Harness: Self-Improving Agent Harnesses via Bandit-Guided Compositional Evolution
**Source:** https://arxiv.org/abs/2610.05300 — Zhiwei Shang et al.; **2026-10-04 preprint, newly recovered**, *not* a November publication. **Status:** strong composition/selection ablations at a controlled **candidate-evaluation** cap.

- **Loop:** role-specific module slots with fixed executable interfaces and bounded implementation pools; full-covariance **LinUCB** predicts scores/uncertainty for untested combinations; mixed-start coordinate ascent proposes complete harnesses; evaluate actual end-to-end tasks and update bandit statistics; use validation traces to generate **new code implementations** for module pools. LLM proposer/executor weights remain **frozen**. Learning a linear surrogate's coefficients is **not** H3 neural evolver training.
- **Fixed-cap comparison:** **40 complete candidate evaluations per method** (MESH 40×1, Meta-Harness 20×2). Held-out Text macro-average **56.33 vs 50.63**, Math pass@1 **53.21 vs 46.20**, LiveCodeBench cap-8 **77 vs 75**, ScienceWorld progress **58.10 vs 53.10**; each **different metric** is reported on a 0–100 scale, not necessarily a common success rate. Initial harness designs differ across optimizers.
- **Ablations:** on Text, random composition **48.80**, no UCB uncertainty **51.70**, full **56.33**; frozen module pools **51.20**, refreshed without historical traces **53.80**, full **56.33**. Thus both *which composition to test* and *which executable implementations to evolve* add observable value.
- **Cost / transfer:** aggregate reported **search+test $166.61 vs $195.05** (−**14.6%**) and **test-only $1.98 vs $3.55** (−**44.2%**) in the paper's priced workloads; these are **not universal** savings. Frozen code transfer is probed on additional models without new search; no full multi-domain old-task retention or independent exploit evaluation. Fixed interfaces and linear interaction assumptions limit generality.

### Qualified adjoining evidence, not promoted to a general H2 breakthrough

- **TTHE, v3 2026-11-04:** https://arxiv.org/abs/2607.08124 — frozen solver/proposer/judge iteratively edit and choose executable harness code from **unlabeled test-batch execution proxies**; the candidate is scored on that same batch and carried forward. **H2 transductive test-time evolution**, but *not* a disjoint evaluation of future-batch improvement; selection proxies and compute require audit.
- **HarnessNet, v2 2026-11-06:** https://arxiv.org/abs/2610.15221 — frozen local optimizers evolve forward harnesses in a hierarchy of Agentron nodes with decomposed feedback. Comparable reported AgentBench gains at less **time/tokens per optimizer call**, but total distributed system compute, transfer independence, shared-state consistency and real privacy isolation require more evidence. H2 with multi-agent orchestration, **not** H4 merely because it is joint among agents.
- **REINS, 2026-11-07:** https://arxiv.org/abs/2611.10748 — verified LLM-generated plans are consolidated into indexed rule memory for trajectory planning, with frozen LLM weights (authors mark accepted NeurIPS 2026). **Restricted procedural-memory H2-adjacent**, not evidence of arbitrary executable harness source-code search.

## October 2026 evidence (retained with updated interpretation)

### Verifier–Harness Co-Evolution for Training-Free Self-Improvement on Open-Ended Tasks (UCoE)
- **Authors / date / status:** Tianyi Xu, Yaolun Zhang, Yiran Wu, Joe Nguyen, Shengyu Dai, Saba Moeinizade, Zhenwen Shao, Qingyun Wu, Huazheng Wang; **2026-10-13**, arXiv preprint.
- **Source:** https://arxiv.org/abs/2610.17609 ; code reported at https://github.com/tianyi0216/Unified-Co-Evolution .
- **Mechanism:** all actor and verifier-model weights **frozen**. UCoE generates and selects *executable verifier programs*, selected on contrast families and worst-case discrimination ("driving capacity"); the verifier diagnoses a draft, controls one revision and acceptance, and gates a **bounded procedural-memory update**. Subsequent accepted repairs change future harness state; verifier code also evolves. This is **verifier-program ↔ harness-state co-evolution, not H3 or H4**.
- **Evidence:** against matched direct generation on six open-ended benchmarks, reported **59.00% and 57.19%** tie-adjusted win rates for Qwen3-8B and Qwen3.8-27B. On three verifiable benchmarks, task accuracy increases **36.06% → 38.48%**. The coding-agent harness demonstration on **75 SpreadsheetBench-2 tasks** reports exact match **17.3% → 22.7%**; small-sample transfer probe, not proof of broad deployment benefit.
- **Limitations:** open-ended scoring is itself model-judged; contrast families may miss real errors; one mistaken verifier decision can contaminate persistent harness state. Extra semantic evaluations raise cost. Outcome/preference gains are sensitive to evaluators and benchmark setup.

### Harness Self-Evolution: Theory, Algorithms, Evaluation, Applications, and Impact (survey/working draft)
- **Authors / date / status:** Chuyang Wei, Haoxiang Guan, Minghang Zhu, Kexin Zhou, Jiyan He, Yifei Shen; **2026-10-12 working draft**, not independently peer-reviewed on this review.
- **Sources:** https://zgcagi.github.io/Harness-RSI/ ; companion reading list https://github.com/zgcagi/Harness-RSI .
- **Contribution:** surveys agent improvements via instructions, external memory, workflows, tools and runtime modification **without weight changes**; explicitly separates selection, activation, attribution and improvement evidence.
- **Audit reported by authors:** 95 methods included; 93 have a primary comparison; **zero** of their 93 scored methods meet *all four* proposed evidence criteria (26 none, 27 one, 33 two, 7 three). Particularly few meet their activation and attribution standards. **These are rubric-dependent audit results, not an objective ranking of each method's validity**; the corpus stops at **2026-10-08**, so it omits UCoE and future work. This is a valuable checklist for future watchers.

### Successive Scale Racing (SSR): Forging More Tasks into Better Harnesses — Jingzhe Liu et al.

- **Primary:** https://arxiv.org/abs/2610.28815 (2026-10-20, preprint). **Key October H2 evidence on search allocation.**
- **Loop:** executor and proposer weights **frozen**. Representative Evidence Ranking (RER) chooses high-quality, nonredundant failure records; a fixed-weight proposer makes harness edits from nested 25/50/75/100% evidence subsets; **Successive Scale Racing** tests alternative executable harnesses on progressively larger shared batches, rejecting weak candidates and promoting a strict empirical winner. Optimizes prompts, scripts and control artifacts, not weights. Note: a series of challenger candidates is not an unrestricted archive of all surviving variants.
- **Evaluation:** SWE-bench Pro Verified (80 train/20 selection/100 held-out), DeepSWE (50/13/50) and GAIA-2 (80/20/100), on Codex/GPT-5.5 and Claude Code/Opus 4.8; the headline averages use three evolution runs and three final test rollouts.
- **Results:** Codex SSR reports **65.7/68.0/38.0%**, vs strongest prior comparator **62.7/66.7/36.3%** on those benchmarks. Claude Code reports **63.3/65.3/36.0%**, vs **62.0/64.0/34.3%**. Differences of **1.3–3.0 percentage points** require caution: limited seeds, no robust multi-comparison significance claim. In an additional 12-candidate selection audit, racing achieved **65.3% vs 65.7%** for exhaustive validation, while using **40% of validation executions**. This **does not** mean evolution as a whole costs 60% less: candidate generation and training-task rollouts still count.
- **Ablations/budget:** evidence scaling 40→200 tasks also **increases** execution allowance, so is not a fixed-compute scaling result; equal-cap comparisons support representative evidence and multiscale generation, but smaller than headline gains. Racing guarantees apply to a bounded validation pool/round, not prospective deployment under adaptive reuse.
- **Threats:** reuse of some training trajectories in selection, benchmark-specific edit preferences, costly search and unsandboxed mutable code risks; need held-out domain transfer, tool/version drift and uncertainty estimates before describing broad autonomous improvement.

### Are Self-Evolving Agents Continual Learners? — Xiaoyin Chen et al.

- **Primary:** https://arxiv.org/abs/2610.25858 (2026-10-19, preprint). **Important counterevidence on retention**.
- **Setup:** one frozen Gemini 3.6 Flash model, four ordered task-distribution streams (BIRD, BFCL, ScienceWorld and mixtures; roughly 100–200 tasks). Compares **ReasoningBank** (retrieved external experiences; boundary with memory management), **GEPA** (global strategy/prompt rewrites) and **Meta-Harness** (prompt, skills, memory and executable harness.py edits, validated before admission).
- **Results:** across streams, GEPA ends at **+3.7 pp** while exhibiting **plasticity +6.2** and **stability −4.3 pp**; ReasoningBank **+2.5** / **+3.3** / **−1.9**; Meta-Harness **+1.4** / **+2.2** / **−2.1**. These are stream/decomposition statistics, not absolute success rates. A topic-drift GEPA case initially gains +7.5 points, then loses 9.5 to finish at −2.0.
- **Mechanisms:** global prompt updates interfere with unrelated skills or overwrite earlier instructions; memory retrieval can collide when similar-looking requests require *opposite* workflows. Stricter validation gates can reject harmful candidates but also reduce adaptation.
- **Limits:** single frozen model, selected task streams, relatively short trajectories; insufficient to rank long-run general-purpose memory architectures. **Implication:** measure **the complete old-versus-new task performance matrix**, not just average score on the newest batch.

### Rethinking the Evaluation of Harness Evolution for Agents — Yike Wang et al.

- **Primary:** https://arxiv.org/abs/2607.12227 (2026-07-14; updated 2026-10-05, v4). **Retained July evidence, revised 2026-10-05**; not a new October 20 paper.
- **Mechanism and controlled question:** compared fixed-weight, batch/per-task harness evolution against **parallel sampling and sequential refinement** of actual task solutions on Terminal-Bench 2.1, with matching K=5 feedback/inference attempts on three frozen frontier models (Opus 4.6, GPT-5.4, GPT-5.4 mini). Direct task-level sampling is **not** H2 but is a necessary budget-matched control.
- **Negative evidence:** without unit tests, **72.3% parallel sampling** vs **67.4% harness evolution** pass@1; with unit tests/oracle selection, **82.0%** vs **69.7%** pass@1. On **34 disjoint held-out Terminal-Bench tasks** (45 training/10 selection), evolved-vs-static success is **64.5 vs 63.3** (Opus), **72.1 vs 72.1** (GPT-5.4), **53.0 vs 54.4** (mini): **63.2% average in both groups**. Distinguish pass@1 from oracle-selected pass@5.
- **Positive boundary:** task-specific evolution shows stronger gains in long-horizon ARC-AGI-3 / EdgeBench games with granular environmental feedback. Reported **RHAE efficiency scores**, e.g. **77.5 vs 44.3** in one setup, are **not success percentages**, nor evidence of reusable harness transfer.
- **Limits:** benchmark/version/model specificity; estimates may exclude harness-edit overhead; no broad production test. **Interpretation:** H2 helps when experience yields *reusable structural bottleneck fixes*, not automatically when feedback could instead fund more direct attempts.

### Harmony Harness: Multi-Objective Self-Evolution of Agent Harnesses — Weichen Yu et al.

- **Primary:** https://arxiv.org/abs/2610.15150 (2026-10-10, preprint); first introduced before this review.
- **Loop:** frozen Gemini 3.6 Flash proposer/executor; executable, rollbackable candidate edits to tools/skills/control logic, with an evolving Pareto population over **functional correctness AND exploit resistance**. Decomposition distinguishes portable vs environment-specific artifacts; dynamic task-time composition picks components. **H2**, not evolver neural-weight training.
- **Results:** on held-out SecRepoBench, **secure-pass@1 (functional AND secure)** rises **50.0→86.7% in-domain** and **36.7→66.7% OOD**. On BaxBench, reported mean **61.3%** vs **42.9%** baseline. The reported multiobjective ablation favors decomposition-based search, but task samples are small (e.g. 30/30/30 SecRepoBench; 28/28/28 BaxBench).
- **Counterevidence within the paper:** an alternate admission/validation criterion obtains **perfect in-sample scores through grader exploitation**. Thus a high in-sample 'secure' reward can indicate **reward hacking**, not real safety. Some OOD transfer evaluations use related benchmark families; compute and generated-code sandboxing need fuller accounting.
- **Implication:** carry safety as its own objective with independently executable, held-out attack tests; don't infer safety from task completion.

### HERA: Harness–Environment Co-Evolution for Reliable Agentic Abstention — Han Luo et al.

- **Primary:** https://arxiv.org/abs/2610.06563 (2026-10-05, preprint).
- **Loop:** frozen proposer/executor; evolve executable harness alongside **verified feasible/impossible task–environment pairs** to diagnose failures. Revises the harness, evaluates and generates fresh environment challenges; co-evolving an environment is still **H2** so long as neural weights are unchanged.
- **Held-out:** in a **60-pair** test set, abstention **61.7→83.3%**, feasible-task completion **68.3→76.7%** and paired success **48.3→70.0%**. A simpler 'generate from initial failures' baseline gets **73.3% paired success**, however, *better* than HERA on that conjunctive metric. Harness transfer to 19 other fixed models is reported; model and search budgets may differ.
- **Limits:** small generated environments and author-controlled verifiers, limited evidence for real-world feasibility judgments, hidden costs of task generation, and uncertain transfer beyond related simulator/task families. Record **all metrics**, not only the winning abstention figure.

### Scale and Selection for Visual-Interface Robot Agents — Zhijie Wei et al.

- **Primary:** https://arxiv.org/abs/2609.39304 (2026-09-30, v4 2026-10-22). An important **classification boundary**.
- **Clean H2 stage:** frozen executor and optimizer, repeated patch proposals to an executable screenshot-to-action harness, challenger/incumbent tests on identical cases and strict promotion across **30 rounds**. Batch size up to **100** produces **51→67%** success on **100 disjoint held-out LIBERO rollouts**. Unconditional acceptance in low-data settings can regress **42→34%** over 10 rounds; larger batches also spend more compute.
- **Separate trained-policy stage:** the work later distills a learned VLA executor from evolved-harness trajectories, reporting RoboCasa365 **62.2%** for the distilled policy and **71.2%** when combined with the harness. These results **must not be counted as frozen-weight H2**. Determine H4 status from the actual *coupling*, rather than assuming all stages are joint training.
- **Limitations:** simulated robotics, small held-out samples, repeated training-case reuse, rollouts cost and robustness to a changed task distribution.

## Earlier mechanism anchors and classification boundaries (retained)

### Agentic Harness Engineering (AHE) — Jiahang Lin et al.
- **Source:** https://arxiv.org/abs/2604.25850 (2026-04-28, revised 2026-05-18, v4).
- **Mechanism:** autonomous edits to file-exposed harness components, compressed trajectory/experience observability and predictions paired with subsequent task outcomes; edits are revertible. **No learned evolver/actor weight update** in the reported harness optimization.
- **Evidence:** Terminal-Bench 2 pass@1 **69.7% → 77.0%** after ten iterations; paper reports transfer across SWE-bench Verified and three alternate model families (approximately +5.1 to +10.1 pp on Terminal-Bench 2). Ablations favor tools, middleware and memory over prompt-only revisions.
- **Limitation:** controlled coding workloads and specific candidate-evaluation budget; proper matched token/rollout accounting and hidden test selection are important.

### Meta-Harness: End-to-End Optimization of Model Harnesses — Yoonho Lee et al.
- **Source:** https://arxiv.org/abs/2603.28052 (2026-03-30, arXiv).
- **Mechanism:** model proposes edits to executable context-management/harness code while consulting a filesystem with **full candidate code, scores and raw traces**. Neural weights frozen.
- **Evidence:** +7.7 accuracy points over reference context-management system on online text classification while using about four times fewer context tokens; +4.7 points average accuracy on 200 IMO-level retrieval-augmented math problems across five held-out models; also tests coding.
- **Ablation:** access to full traces substantially beats scores-only or LLM-generated summary conditions; supports evidence availability as a design decision, not only the prompt.
- **Limitation:** different benchmarks/compute units; best-of-N search and proposer capability must be matched.

### Darwin Gödel Machine (DGM) — Jenny Zhang et al.; A Self-Improving Coding Agent (SICA) — Maxime Robeyns et al.
- **Primary sources:** https://arxiv.org/abs/2505.22954 (DGM, 2025-05-29); https://arxiv.org/abs/2504.15228 (SICA, 2025-04-21).
- **Mechanisms:** SICA directly edits agent implementation; DGM uses an **archive/tree** of self-modified coding agent implementations and open-ended branch sampling. **Model weights stay fixed**; the implementation evolves.
- **Reported DGM results:** SWE-bench **20.0% → 50.0%**, Polyglot **14.2% → 30.7%** in its stated setup. SICA reported **17% → 53%** on a random SWE-bench Verified subset.
- **Limitations:** benchmarks/subsets, model and executor budget vary; uncontrolled code mutation, potential reward hacking; do not compare these headline gains to 2026 papers unless task/model/compute are matched.

### Retrospective Harness Optimization (RHO) — Wenbo Pan et al., Microsoft Research et al.
- **Source:** https://arxiv.org/abs/2606.05922 (first 2026-06-04; revised Aug 2026).
- **Mechanism:** retrieve difficult historical tasks, rerun them, propose edits, and select via pairwise **self-preference** without external grading at optimization time. Persistent harness state updated; weights fixed.
- **Reported evidence:** **59% → 78%** SWE-bench Pro success after one retrospective optimization pass in reported evaluation.
- **Limitations:** self-preference can be biased, vulnerable to correlated model errors; unclear representativeness of long-run gains under shifting task distributions. One cycle is weaker evidence for indefinite self-improvement.

### Additional boundaries and benchmark
- [Hierarchical Self-Improvement (HSI)](https://arxiv.org/abs/2608.08466) (Tailin Zhou, 2026-08): frozen LLM modifies harness **and the evolver's strategy code**, not neural weights; thus **H2**, despite the term "meta-evolver".
- [Living-Harness](https://arxiv.org/abs/2607.26598) (Yuetian Du et al., 2026-07): persistent episodic memory/state-graph repairs with fixed model/tools; an H2 **restricted-state** form, not full harness source-code rewriting.
- [EvoHarnessBench](https://arxiv.org/abs/2609.04280) (Salesforce Research et al., 2026-09): **benchmark**, not an evolution algorithm; 17 evolution streams / 802 tasks / 520 tools / 42 skills / 62 agents in original paper; documents harness-induced forgetting and adaptation–retention tension.
- [Beyond Prompts / PRISM](https://arxiv.org/abs/2609.05736) is a related restricted search over prompt and tool-boundary middleware, covered primarily in [H1](../h1-harness-engineering/research.md).
- [Evo²](https://arxiv.org/abs/2610.13025) has an automated harness search **plus learned evolver weights**, hence its fully trained configuration is **H3**, not H2. Its frozen-evolver ablation is an H2-compatible comparison.

## Contradiction register and evaluation discipline

| Hypothesis or prior conclusion | Supporting source / mechanism | Disconfirming evidence or condition | Assessment at 2026-11-10 |
| --- | --- | --- | --- |
| Frozen-model agents can improve from executable self-edits | DGM, AHE, Meta-Harness, SSR, MESH, Meta² | Gains vary by tasks, editable surfaces and budget; *Rethinking Evaluation* 63.2 vs 63.2 held-out | **Supported in specific evaluations; broad generality unproven.** |
| A strong final champion preserves old competence | Selected champion scores; regression gates | EvoHarnessBench; October continual study; Zhao 94→32%; Beneath the Surface all 16 gain/loss | **Contradicted as general claim.** |
| More evidence, strict selection or a higher-scoring parent always helps | SSR RER/racing; score-gated search | EvoGroup no-filter ablation improves; EvoAudit parent potential and stricter gates can discard wins | **Mechanism-/workload-specific.** |
| Search topology needs only greedy single-lineage selection | AHE/Meta-Harness show sequential gains | DGM branching, MESH recombination and Harmony Pareto give viable alternatives | **Unsettled at matched total costs; compare lineage diversity and regret.** |
| Training the evolver is required for reusable meta-improvement | H3 Evo² is a distinct trained-evolver claim | H2 textual Meta² and non-neural MESH improve without weight updates | **False as necessity claim; H2 vs H3 amortized comparison still open.** |
| Better mean score means better deployment | In-domain benchmark improvements | Beneath the Surface shows lost covered tasks and cost premiums | **Contradicted.** |
| Persisting cross-task code edits compounds gains | Continual global-harness ambitions | Meta² persistence ablation worsens; Zhao across-domain forgetting | **Unproven; favor scoped/persistent comparison, not a blanket ban.** |
| Transfer on a second model/dataset establishes portability | AHE/MESH frozen code transfer, HERA, EvoGroup, Meta² | EvoGroup DeepSeek negative vs seed; Meta² reconstructs per-model meta-skill | **Report exactly which artifact, task split and model were held fixed.** |
| Candidate reward implies functional and secure outcomes | Harmony Pareto secure-pass improvements | Harmony alternative gate exploited in-sample grader; mutable code can tamper with checks | **Require independent functional and exploit oracles plus deterministic isolation.** |
| More complicated co-evolution is always better | HERA verifier/environment curriculum | Simpler HERA baseline exceeds paired-success (73.3 vs 70.0) | **Contradicted as a universal design rule.** |
| Test-time improvements prove future-batch generalization | TTHE unlabeled execution proxies | Transductive selection and score on same batch; no untouched next-batch benefit implied | **Future-batch claim not established.** |

### Minimum reproducibility and safety protocol for future H2 reviews

1. **Identity and editable surface:** state task executor, proposer/evolver, judge, versions and frozen/trainable weights. Archive real code diffs and allowed files/tool interfaces. Distinguish a **learned neural policy** from non-neural bandit fitting and in-context or textual adaptation.
2. **Decompose budget:** account for candidate generation, invalid candidates, number of task executions and repeated attempts, judge calls, selection runs, token/price, wall-clock and deployment-time overhead. Match search **and** end-to-end cost, not only rollout count. Compare direct solution sampling and static-best-of-N.
3. **Separate feedback and final tests:** pre-register Train, adaptive Selection and **untouched Test**, never let held-out labels, test verifier feedback or secure hidden tests enter proposer or judge. If selection occurs on the target test batch (TTHE), label results **transductive**, and add a fresh subsequent batch for prospective transfer.
4. **Report all transitions:** for old/new domains and each candidate generation, retain old-task retention and new-task acquisition, **Avg@k**, **Pass@k**, gained/lost task IDs, confidence intervals over *search seeds* and *executor rollouts*, and run-to-run stability.
5. **Isolate search-operator causality:** ablate proposer edits vs trace access, evidence filtering, parent choice, branching/archive depth, pool refresh, surrogate exploration, verifier quality, and admission gates. Avoid crediting larger task/evaluation budgets to the optimization method.
6. **Stress transfer and safety:** freeze the final artifacts before model swaps or unrelated benchmark families; test tool/version drift, adversarial tasks and tasks previously solved. Execute candidate code in sandboxes with external immutable validators, permissions at side-effect boundaries, resource/egress caps, audit logs and rollback.
7. **Decision rule:** call an advance *substantive* only when it improves a previously unresolved mechanism or materially changes confidence in a claim. Preserve **contradictory evidence and no-gain conditions** in the living synthesis rather than accumulating chronological reports.

**Open research questions:** when to carry global patches vs local edits; how to value an archive's future *evolvability*, not only current score; whether diversity-aware/evidence-weighted search beats direct attempts on fresh tasks at equal full spend; whether any method provides robust cross-domain retention without per-domain revalidation; how to prevent self-evolved checkers from exploiting their own reward; and whether H2 textual/non-neural meta-learning retains an efficiency advantage over trained H3 evolvers after amortized total cost.
